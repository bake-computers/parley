# Landing Page Learnings

## Task 1: Create apps/web TanStack Start Project

### Key Findings

1. **routeTree.gen.ts is auto-generated**: The `routeTree.gen.ts` file is generated by TanStack Router during the build process (via `@tanstack/router-plugin`). It is NOT supposed to exist before build. TypeScript compilation will fail if you try to reference it directly without first running a build.

2. **Component typing issue**: TanStack Start's `createRootRoute` expects a component that receives `{}` (empty props), not `{ children: ReactNode }`. The `{ children }` prop pattern only works when using TanStack Router's context-aware routing. For a simple landing page with no router context, use a no-argument component function.

3. **Minimal landing page structure**: The web app doesn't need:
   - QueryClient
   - TanStackDevtools / TanStackRouterDevtoolsPanel / TanStackQueryDevtools
   - `setupRouterSsrQueryIntegration`
   - Hyperdrive / KV / Queue bindings
   - `@parley/db`, `@parley/auth`, `@parley/core`
   - `@tanstack/react-query`, `@tanstack/react-table`, etc.

4. **Plugin order in vite.config.ts matters**:

   ```
   cloudflare (with viteEnvironment: { name: 'ssr' }) → tailwindcss → tanstackStart → viteReact
   ```

5. **No devtools plugin needed**: Unlike HQ, the landing page doesn't need `@tanstack/devtools-vite`.

6. **Turbo pipeline**: The `build:web` pipeline was added to `turbo.json` following the same pattern as `build:hq`.

### What

1. **account** - register, unregister, me, refresh (4 subcommands)
2. **stats** - top-level options: username, platform, season
3. **team** - create
4. **queue** - start, status, cancel (3 subcommands)
5. **ping** - no subcommands
6. **tournament** - create, browse, view, join, leave, start, cancel, forfeit (7 subcommands, split into browse/lifecycle)
7. **limit** - set, clear, show (3 subcommands)
8. **leaderboard** - top-level options: scope, platform, min_matches

### Key findings

- Tournament command split into `tournamentBrowseCommandData` and `tournamentLifecycleCommandData` to match help.ts category organization
- Limit command appears in both "Tournaments II / Admin" and "Utility / Admin" categories per help.ts
- All descriptions extracted verbatim from handler files (account.ts, stats.ts, team.ts, leaderboard.ts, ping.ts)
- Choices values stored as strings (e.g., "auto", "pc", "4" for integer options)
- `autocomplete: true` marked for tournament `id` options and stats `season`
